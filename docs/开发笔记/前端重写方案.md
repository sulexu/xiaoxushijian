# 前端重写方案（Tailwind + daisyUI）

> 2.5.1 期间定。**已完成的每一步都验证过（测试 + 截图），没验证的不写在这里。**

---

## 一、为什么必须"改造"而不是"直接加"（四次实测的结论）

把 Tailwind + daisyUI 接进来之后界面**当场坏掉**。做了四次构建实验定位：

| 构建内容 | tw.css | 界面 | 根因 |
|---|---|---|---|
| 完整 Tailwind + daisyUI | 246 KB | ❌ hero 区文字全叠住 | daisyUI 的 `.hero{display:grid}` + `.hero>*{grid-row-start:1}` 跟应用的 `.hero` 撞名 |
| 去掉 preflight，只留 utilities | 243 KB | ❌ 同样叠住 | 撞的是**组件类**（.card/.btn/.modal/.tab/.input/.select/.table…），不是 reset |
| 加 `prefix(ds-)` 去撞名 | 26.9 KB | ❌ **换成图标坏** | Tailwind 的 preflight 把内联 `<svg>` reset 成 `display:block`，图标换行、顶栏图标消失 |
| **prefix + 去 preflight** | 23.3 KB | ✅ **正常** | 两个问题都解决 |

**排除了两个常见嫌疑**（都不是）：
- 不是变量撞车：tw.css 202 个变量 vs style.css 50 个，**同名 0 个**
- 不是层叠顺序：`style.css` 未分层本该赢，但**它没写过 `display`/`font-size` 这类默认值**，
  层叠只能决定"同一属性谁赢"，**没写的属性管不着** —— 所以放进低优先级 layer 也救不回来

**得到的规矩**：给一个成型项目中途加 preflight = 换地基。
只取 `theme.css` + `utilities.css`（**两个都要，且不要 `tailwindcss` 主包**）。

## 二、已经做完的（都验证过）

| 项 | 状态 |
|---|---|
| 装依赖 | ✅ `tailwindcss 4.3.3` + `daisyui 5.7.42` + `@tailwindcss/cli`（34 个包） |
| 构建脚本 | ✅ 根 `package.json`：`npm run css`（构建）/ `npm run css:watch`（监听） |
| 构建入口 | ✅ `static/_src.css`（下划线开头 → **不会打进安装包**，它只是构建输入） |
| 产物 | ✅ `static/tw.css`，23.3 KB |
| 接线 | ✅ `index.html` 里 `<link href="/static/tw.css">` 排在 `style.css` **之前** |
| **设计令牌映射** | ✅ daisyUI 的颜色**指向项目原有变量** —— `--color-base-100:var(--card)`、`--color-primary:var(--blue)` 等。所以那 **7 套配色 × 深浅两模式会自动驱动 daisyUI**，不需要维护第二套色板 |
| **避开撞名** | ✅ daisyUI 全部加 `ds-` 前缀 → 应用可以用 `.ds-card` / `.ds-btn`，跟旧类互不干扰 |
| 回归 | ✅ 前端 **342 项**测试全绿；总览页截图确认外观未变 |

**关键收益**：加了前缀之后，**新旧可以共存** ——
没迁的页面继续用手写 CSS，迁好的页面用 `ds-*`，
**中间任何时刻程序都是能用的**，不会出现"全站坏掉等重写完"。
（不做前缀的话，1250 行 CSS + 262 个函数必须一次性改完，而那期间程序完全不可用。）

## 三、接下去的迁移（一页一页来，每页验证）

| 步 | 范围 | 说明 |
|---|---|---|
| **1** | 总览页 | `.hero` `.kpis` `.kpi` `.card` `.grid2` → 改用 `ds-*` 组件 + Tailwind 原子类 |
| **2** | 公共件 | `.btn` `.modal` `.badge` `.tab` `.input` `.select`（这些用得最广，改完收益最大） |
| **3** | 逐页 | 账单 → 打卡 → 物资 → 待办 → 日记 → 随笔 → 回忆书 → 设置 |
| **4** | 清理 | 删掉 `style.css` 里已被取代的部分（**删之前确认没有页面还在用**） |

⚠ **每步都要**：`npm run css` → 跑前端 342 项 → 截图确认 → 才进下一步。
⚠ 第 1~3 步之间界面会是"一半新一半旧"，**这是分步的必然结果，不是坏了**。
⚠ 内联 `style="..."` 散在 262 个函数的模板字符串里，**没法自动化**，只能一个页面一个页面过。

## 四、代价（说清楚，不藏）

| 现在 | 之后 |
|---|---|
| 改样式 → 刷新浏览器 | 改样式 → **跑 `npm run css`** → 刷新。忘了跑就看不到效果，**而且不报错** |
| 零构建、零依赖 | 多 `node_modules`（34 包）+ 构建产物 `tw.css`（23 KB） |
| 一份 `style.css` 说了算 | daisyUI 主题 + Tailwind 原子类 + 旧 CSS，三处都能定义样式 |

**打包不受影响**：`tw.css` 是普通 CSS，跟 `style.css` 一起进包。
**运行时不联网** —— 这点没变（Tailwind 是构建时依赖）。
