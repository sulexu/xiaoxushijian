## 2. 顺手报一个真 bug（不需要你做决定，但需要你确认要不要修）

**设置 → 数据备份，那张卡上的目录提示是写死的，只在一种情况下是对的。**

`static/app.js:4555`：

```js
<span class="mini">${list.length} 份备份 · 目录：个人信息统计\_自动备份\</span>
```

这句话**不读 `backup_dir` 设置**，是硬编码的字符串。所以：

- 你没改过备份目录 → 显示正确。
- 你把备份目录改到 U 盘（`server.py:1337` 支持这个设置）→ **它仍然显示
  `个人信息统计\_自动备份\`，而真正的备份在 U 盘。**

而且 `server.py:267` 的注释说明后端**本来就打算把「当前目录 + 老目录」都发出来**，
接线没接到前端这一句上。

**为什么值得修（对你）：** 这属于你自己定的第 5.4 条
「事实变了、说法没变」—— 界面在说一件不成立的事，而且说的恰好是
**「我的备份在哪」**。按第 5.3 条，你更不能接受的是「不吭声」：
这里它不但不吭声，还指了个错的地方。

**顺带一个更实际的问题：** `backup_dir` 现在**在设置界面里没有输入框**
（我在 `static/app.js` 全文搜过，没有对应的控件），只能在配置文件里改。
也就是说「把备份放到 U 盘」这条路，**现在界面上走不通**。

## 3. 确实没有的功能（0 命中，已核实）

这两条是本文唯一「确认是缺口」的功能项。列出来是为了给你事实，不是替你排序。

### 3.1 课表 / 单双周

- **现状**：0 命中。系统里的日期维度是「日历 + 学期 + 月 + 日」，
  **没有「第几周」「这一节是什么课」的概念**。
- **它和现有功能的关系**：`check_month` 按月存、账单按 `sem` 学期分区 ——
  说明你已经在用「学期」这个学生特有的时间单位，只是**没往「周」这一层走**。
- **改动涉及**：新表 + 新页面 + 一个新的时间维度（周次要能从开学日推算）。
- **风险点（按 `项目交接.md` A 类）**：A 类 11 条坑里，**6 条**和存储/迁移直接相关
  （A4 事务分域 / A6 缺表误判成缺列 / A7 加列 / A8 迁移脚本自己吃自己 /
  A10 断月 / A11 新建学期没写库）。
  **新课表是本清单里唯一需要动存储结构的一项**，风险最高。

### 3.2 成绩 / 学分 / 绩点

- **现状**：0 命中。
- **它和现有功能的关系**：`cat` 表已经是「按 `sem` 分区」的模式
  （`server.py:2199 _cats_of(sem)`），成绩表可以照这个模式做。
- **改动涉及**：新表 + 新页面。
- **风险点**：同样是新存储结构。
