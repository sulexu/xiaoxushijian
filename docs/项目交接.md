## 4. 架构与必须遵守的约定

### 4.1 存储

- **数据住 SQLite**，Excel 降级成「导出格式」。三本原件还在原地、内容未改。
- 表：`bill` `tail` `budget` `cat`（带 `sem` 学期）、`check_val`（窄表）、
  `check_month` `check_cfg` `check_item`、`dream`、`stock` `stock_header`、
  `todo` `em_field` `em_contact` `attach` `kv`
- **公式列一律不存**（物资的剩余天数/效期状态/补货状态/开封后到期）——
  从 Excel 读到的是缓存值，存下来就是会悄悄过期的死数据。
- 笔记是 **Markdown 文件**（`笔记\{日报,周报,月报}\`），**不进数据库**。

### 4.2 后端三条铁律

```python
# ① 路由返回值必须是 3 元组 (ok, msg, data)
return True, "已保存", {...}          # ✓
return {"items": ...}                 # ✗ 前端拿到 undefined，点了没反应还不报错

# ② loader 的第一个参数必须是 path
#    cached(path, loader) 是按 loader(path) 调的
def load_bill(path): ...              # ✓
def load_bill(sem, path): ...         # ✗ 文件路径被当学期名，查出 0 条且不报错

# ③ 事务要分域
with store.tx("bill") as c: ...       # 记一笔账不该让打卡页也弹「数据在别处被改过」
```

### 4.3 加设置项

**必须同时登记进 `SETTINGS_DEFAULTS`**，否则 `settings_load()` 会把它悄悄丢掉。
（`notes_salt` 没登记，导致过「加密笔记全部打不开」）

### 4.4 前端

- **`afterRenderSettings()` 是唯一的「渲染完要绑哪些事件」清单。**
  新控件在那一处登记，不要再手抄第二份（见坑 B1）。
- 颜色一律用 `colorOf()` / `hslCss()`，**不要手写 hsl**（见坑 B4）。
- 图表数据变了要 `setOption(opt, true)`（notMerge），否则旧系列残留。
- **脚本加载顺序在 `static/index.html` 里，`core.js` 必须排第一。**
  前端已经从「一个 app.js」开始拆（2026-09-20 走出第一步），
  多个 `<script>` 共享同一个全局环境，所以**不需要任何构建工具**，改完刷新就行。
  ⚠ 三条规矩：
  1. 新文件插在 `core.js` **之后**。顺序错了就是白屏。
  2. **绝不在两个文件里定义同名函数** —— JS 是后定义者胜、而且**不报错**，
     会静默盖掉前一个。这条已经真栽过：`copyText` 被定义两遍，
     后那个（没有降级兜底）赢了，于是「复制失败要退回老办法」那段**从来没生效过**。
  3. 搬函数之前先跑 `node _函数清单.js --dump`，搬完跑 `--compare`；
     再用 `node _验证拆分无损.js` 确认没有业务代码被改。工具见第 6 节。

### 4.6 ⚠ 三套「加载器」必须同步（2026-09-20 真栽了）

前端有**三个地方各自决定加载哪些脚本**，改一个要想到另两个：

| 谁 | 在哪 | 说明 |
|---|---|---|
| 真页面 | `static/index.html` 的 `<script src>` | 权威来源 |
| 测试台 | `static/_test.html` 开头那段 IIFE | **它自己建 script 标签**，原来写死 `app.js` |
| 验证脚本 | `_前端源码.js` 的 `allSource()` | 读 `index.html` 拼源码，供 node 抠函数 |

**实测教训**：加了 `core.js` 之后忘了改测试台 → 测试台里 `$` / `esc` / `toast`

### 4.7 ⚠⚠ 不许用 `window.prompt()`（这条只在打包版犯病）

**背景**：`prompt()` 从 **Electron 16 起被官方移除**（BREAKING CHANGE 原文：
`window.prompt() is no longer supported`），本项目用 **Electron 44**。
也就是说打包版里所有 `prompt()` 都是**点了完全没反应**，而**浏览器里一切正常**。

**2024-09-20（2.4.7）实测**：一处都没发现地活了很久，直到用户说
「保存记法点击没反应」。顺着查下去发现**同一个原因一共 6 处** ——
账单类别改名/新增、新建学期、日记导出、随笔导出，全都在打包版里是死的。

**规矩**：

| 想干的事 | 用什么 |
|---|---|
| 问用户要一段文字 | **`askText({title, label, value, ph, hint, ok, multi, icon})`** ——
  `static/core.js`，返回 Promise（确定→字符串，**取消→null**） |
| 只要一个「是/否」 | `confirm()` **可以用** —— Electron 里它是**支持**的 |
| 提示/报错 | `toast()` / `modal()` |

```js
// ✅ 对
const name = await askText({title:"新建学期", label:"学期名", ph:"大二下"});
if (name === null) return;              // 用户取消 —— 必须判 null，\n                                        // 空字符串是"确定了但没填"，两件事
// ❌ 错：打包版里直接返回 undefined/null，函数当场 return，看着像没反应
const name = prompt("新建学期叫什么？");
```

⚠ **调用 `askText` 的那个箭头函数必须是 `async`** —— 漏了就是
`SyntaxError: await is only valid in async functions`，而且 node 报的行号指向
**调用处**而不是函数声明处，看着像别的地方错。

⚠ **为什么这类 bug 特别危险**：开发和测试**全在浏览器里跑**（无头 Chrome）。
Chrome 里 `prompt()` 好好的，所以自测全绿、手测也全绿 ——
**只有真装了那个安装包才会露出来**。这是本项目第一条「只存在于打包版」的 bug。

**由此得出的一条更宽的规矩**：凡是碰 **浏览器 API 与 Electron 有差异**的地方
（`prompt` / `alert` / `confirm` / 剪贴板 / 文件对话框 / 下载），
**「自测全绿」不再等于「打包版没问题」，必须在真安装包里手点一次。**

## 5. 踩过的坑（按类别，每条都真的踩了）

> **2.4.2 新增 H 类：CSS 类名写了、样式没写**（见 H 节）。
> **2.4.6 新增 I / J / K 三类**：说法没跟着事实走、锁自锁、缺字段被当成清空 ——
> 三条都是「不报错、也不崩，但你迟早会撞上」的那种。


### A. 存储 / 后端

| # | 现象 | 根因 / 规矩 |
|---|---|---|
| A1 | 工作线程看不到库路径 | 库路径必须**进程级**，塞 `threading.local` 会让一请求一线程的模型失效 |
| A2 | 每请求漏一个连接、压住 WAL 读锁 | **每线程一条连接，在 `Handler.finish()` 里关** |
| A3 | 查出 0 条且不报错 | 见 4.2 ②：`cached(path, loader)` 是按 `loader(path)` 调的 |
| A4 | 记一笔账，打卡页弹「数据在别处被改过」 | `store.tx()` 要**分域** |
| A5 | `float()` 突然炸 | `to_num()` 解析不出来时返回**原字符串**（不是 None）；`to_date()` 返回 datetime 不是 date |
| A6 | **用户打不开软件** | 早期版把「缺表」误判成「缺列」：`PRAGMA table_info` 对**不存在的表**返回空、不抛异常，于是错误信息骗人。现在 `init()` 会先补缺的列，只对补不上的（主键列）报人话 |
| A7 | `CREATE TABLE IF NOT EXISTS` 不给旧表加列 | 加字段要写 `ALTER TABLE ADD COLUMN`；**主键列加不了**，得重建表 |
| A8 | 迁移脚本自己吃自己 | `_migrate.py` **不能调 `server.load_*`** —— 那些函数已经改成读库了，会「从空库读出来写回同一个空库」还不报错。所以有了冻结的 `_excel_legacy.py` |
| A9 | 加密笔记全部打不开 | 见 4.3 |
| A10 | 断月留窟窿 | `check_ensure` 只补"当前月"，整个月没开机就永远缺那张月表。现在是启动时后台补齐（上限 24 个月） |
| A11 | **新建的学期一条类别都没有** | `semester_create()` 整个函数只动那个 Excel 模板、**一行都没写数据库**，而类别住在 `cat` 表里按 `sem` 分区、`_cats_of()` 死查没兜底。账单页的分类下拉是空的，**可返回的消息还写着「类别和格式都保留」**。2.4.6 修：新建时把类别整份复制过去。⚠ **换存储之后要挨个问一遍：还有谁在写旧的地方？** |

### B. 前端渲染（**这个项目最贵的一课**）

**B1. 「渲染完没做后处理」是慢性病，栽过 5 次。**
典型症状：**元素在、事件没绑，点上去毫无反应，也不报错。**

- 栽过：saveCfg / renderNoteEditor / renderSettings 图标 / 数据分区四张卡
- 最近一次（2.3.4）：`loadSettings()` 里手抄了一份绑定清单，漏了 `bindBg()`
  → 从标签页进设置，「换一张」「去掉背景」**是死按钮**
- **规矩**：`afterRenderSettings()` 是唯一清单，新控件在那里登记一次。

**B2. `insertBefore` 的锚点，栽过三次，一次比一次微妙：**

```js
// ✗ 第一次：先删再问爹
olds.forEach(x => x.remove());
anchor.parentElement.insertBefore(n, ...)   // anchor 自己就在 olds 里 → parentElement 是 null
                                            // TypeError: Cannot read properties of null

// ✗ 第二次：改成先记下来，但记的是「第一个」的下一个兄弟
const next = olds[0].nextSibling;           // 它多半**也在 olds 里**（下一组标题、加一项按钮）
olds.forEach(x => x.remove());              // 一起被删 → 已不在树上
parent.insertBefore(n, next);               // NotFoundError: ... is not a child of this node

// ✓ 正解：取这一串里**最后一个**的后面 —— 按定义它不在删除名单里
const last = olds[olds.length - 1];
const next = last.nextSibling;              // null 表示插到末尾
```
同一个函数改了两版都没修对，**两版报的是同一个错的两种名字**。

**B3. CSS 变量不能自引用。**
`:root.x{--card:color-mix(in srgb, var(--card) 82%,transparent)}` 是循环，
整条声明**作废、静默失效**。所以卡片通透是在 JS 里读实色 → 算 rgba → 写回去。

**B4. ECharts / zrender 的颜色解析按「逗号」切。**
`hsl(36 52% 46%)`（空格分隔）会被解析成长度 1 → 变成 `rgba(0,0,0,0)`
→ **图全空白，还不报错**。必须写成 `hsl(36, 52%, 46%)`。
症状之一是「点了图例之后整张图消失」。

**B5. ECharts 实例的 `_theme` 是它内部的 Theme 对象**，往里写标记会让图全白。
主题名要另存一个变量。

**B6. `body::before/::after` 必须用 `z-index:-1/-2`。**
用 0 会盖在正文上面（有定位的元素永远画在普通流内容之上），整页被糊住。

### C. 数据口径（同一个值算两遍 = 慢性病）

**根子**：Excel → SQLite 迁移时，同一个数在 Python 和 JS 各算了一遍，没有共同来源。

| 坑 | 后果 |
|---|---|
| 睡眠时间是 `'01:49'` 字符串，后端 `_hm()` 不认 | 全算成 0，AI 跟你说「要么没填要么没睡」 |
| 完成率分母写死 5 | 改了打卡项就对不上 |
| 未来日期也算进月完成率 | 月初打开一看「本月完成率 15%」，其实是自己吓自己 |
| **期初余额被当成收入** | 收入饼图凭空多一大块 |
| 「没小睡」语义 | 留空 = 还没记；**0 = 没小睡，判不达标（扣分）**；1~30 = 达标 |

### H. CSS：类名写了、样式没写（2.4.2 补的一类）

**这个项目里最隐蔽的一类 bug —— 因为它什么都不报。**

HTML 里写了一个类名，样式表里从来没有它。浏览器**不报错、不警告**，
那一块就按普通 div 排：该并排的变成上下堆，该 216px 宽的变成整页宽。
你只有在**打开那一页盯着看**的时候才会发现。

| 实例 | 症状 | 什么时候发现的 |
|---|---|---|
| `.nwrap` `.nt` `.ns` `.nedit` `.nmain`（随笔页，2.3.6 加的） | 左边一列被拉成整页宽、「写一篇」按钮横贯整个页面、编辑区掉到列表下面 | **2.4.2**，用户截了张图说「这个按钮不好看」—— 追下去才发现根子不在按钮 |

**规矩：**
1. **新增一个页面/组件，写完 HTML 立刻在浏览器里打开看一眼** ——

2. **能复用就复用**。随笔页那个形状跟日记页**一模一样**（左列表 + 右编辑），

3. 写完之后**搜一下自己起的类名在 style.css 里有没有**：
   `grep -c "nwrap" static/style.css`。一条命令的事。

### I. 「事实变了、说法没变」（2.4.6 补的一类）

**跟 H 是同一个病，只是住在文字里而不是样式里。**

2.0 把数据从 Excel 搬进 SQLite，但**说法没跟着搬**：
界面上二十多处还写着「改动会直接写回 Excel：每日打卡表.xlsx」

你还要用 WPS 打开改」。文档也一样 —— 用户就是拿着一张 Word 截图

| 实例 | 说法 | 事实 |
|---|---|---|
| 三个页面的页脚 | 「改动会直接写回 Excel：xxx.xlsx」 | 写库 |
| 物资页脚 | 「状态列由 Excel 公式自动算」 | 程序算的 |
| 账单页脚 | 「『汇总』『图表』两个 Sheet 依然会自动算好」 | 没这回事了 |
| 隐私页 | 「三个 Excel 始终是明文（你还要用 WPS 打开改）」 | 早不用了 |

| 学期管理 | 「记录 106」 | 那是**打开旧 Excel 数出来的**，库里是 104 |

### J. 锁：不可重入的 LOCK + 自己加锁的辅助函数 = 自锁（2.4.6）

```python
_write_lock = threading.Lock()      # ← 不可重入

def _save_json(path, obj):
    with _write_lock:               # ← 「谁调都自己加一次锁」的写法
        ...

def semester_switch(body):
    with _write_lock:               # ← 先拿住
        _save_data_config()         # → _save_json() → 又去拿同一把锁 → 死在这儿
```

**症状不是报错，是「卡死」**：那个请求永远不返回，而且**锁一直不释放** ——
之后所有写操作（记一笔、打卡、改物资）全部跟着挂起，整个程序看起来就是"卡了"。
查的时候很容易往"慢"或"死循环"上想，其实是自锁。

**规矩：**
1. **一把锁护一件事，而辅助函数总会自己加锁** —— 所以这个项目的
   `_write_lock` **必须是 `threading.RLock()`**。跨线程照样互斥，
   同一个线程可以再进来一次，这才是「辅助函数自己加锁」本来就依赖的前提。
2. **凡是"点一下就没反应"的地方，先去看它是不是持着锁在调另一个加锁的函数。**
3. ⚠ 这条路径**整整几个版本都没有一行测试**（`_自测.py` 和 `_test.html`
   里连一个 `semester` 都没有）。**没有测试的路径 = 没写过的路径**，
   别默认它好的。现在补了 9 条。

### K. 缺字段 ≠ 清空（2.4.6）

```python
v, s = _stock_vs(sheet, col, body.get("value"))
if v is None and s is None:
    c.execute("DELETE FROM stock WHERE ...")     # ← 静默删掉这一格
```

调用方把键名写错（传 `v` 而不是 `value`）→ 服务端读成 `None` →
**删数据、还回一句「已保存」**，从头到尾没有任何错。
一次手写探针就这么把「药品 第2行 数量=10」删了。

**规矩：**
1. **「键不存在」和「值是空」是两件事，永远分开判**：
   `if "value" not in body: return False, "少了 value 字段"`。
   前端清空发的是 `value: ""`，**键一定在** —— 所以这条拦不到正常操作。
2. 一个写接口如果**缺参数会退化成删除**，那它就是个定时炸弹。

### 数据和测试的口径（改之前先读这一段）

- **「收入」有两个数，都发出去，界面上都写清楚名字**：
  `kpi.earned` = 真正挣到的（饼图 / 月柱状图 / AI 评价赚钱能力用它）
  `kpi.inc` = 含期初余额的账面总收入（和 Excel 对账用它）
  `kpi.opening` = 期初余额。**`inc = opening + earned`**，测试钉住了这条。
- **只有 `month_inc_real`（→ cashflow 每月结余预估）继续剔除期初**。
  拿本金当收入去估"每月能剩多少"会得出一个永远达不到的数。
- **改收入口径时，`inc_cat` 里「结余」必须保持独立成类**。它的 `cat`
  在数据里都是「其他收入」，并进去饼图就是一块占 99% 的色块。

### 文档结构（现在**五份**：四份讲程序，一份讲「人」）

| 文件 | 给谁看 | 里面有什么 |
|---|---|---|
| `使用说明.txt` / `.docx` | 用的人 | **功能怎么用**，15 节，无版本历史 |
| `新手说明.txt` / `.docx` | 刚上手的人 | 怎么打开 / 先做哪三件事 / 九个页面各干什么 / 几个最省事的用法 / 数据会不会丢。6 节，**故意写得短** |
| `项目历程.md` / `.docx` | 用的人和改代码的人 | **每个版本动了什么、修的是什么问题、踩了什么坑**，19 个版本，带索引表 |
| `项目交接.md` / `.docx`（本文） | **下一个改代码的**（包括没有上下文的 AI） | 安全红线、架构约定、A–K 类坑、怎么跑测试、怎么打包 |
| `用户需求和决策习惯.md` / `.docx` | **下一个接手的 AI**（尤其是没有上下文的） | 跟他**怎么配合**：他一定要被问、怎么问才有效、他靠「后果」做判断、**他说的前提可能是错的**、我犯过的九次误判、他的原话合集。**动手之前先读这一份。** |

**五份都有 Word 版**，改完源文件要重新生成，别只改 `.txt` / `.md`：

```
python _md_使用说明.py       # → 使用说明.docx（txt → Word 的排版引擎在这）
python _md_新手说明.py       # → 新手说明.docx（import 上面那个，样式不会走样）
python _md转word.py          # → 项目历程 / 项目交接 / 用户需求和决策习惯（md → Word）
```

⚠ **`.md` 那三份必须走 `_md转word.py`，不能拿 Word 直接开 `.md`** ——
那三份里全是表格（版本索引表 + A–K 坑表 + 文档结构 + 误判清单，共 14 张），
Word 打开 `.md` 只会显示一片带竖线的原文，表格得手画。

⚠ 搬家的经过：原来版本流水堆在 `使用说明.txt` 的**最前面**，占了六成篇幅 ——
当手册看得先翻过一堆「改了什么」，当版本记录看又得在 1100 行里翻。
`_拆文档.py` 把它们整体搬进了 `项目历程.md`，**内容一个字没删**。

## 8. 和用户打交道的注意事项

- **中文交流，要「一个一个问题地给方案」。** 喜欢先看方案再动手；
  视觉/口味类的事**一定要给选项让他自己决定**（"再小的事也是我决定"）。
- 说话要直：错了就说错了（例如 2.3.3 那个 `insertBefore` 我只修了一半，
  2.3.4 才修对，这种事要在交付说明里写清楚）。
- 交付时他关心四件事：**改了什么 / 数据会不会丢 / 测试过没有 / 有没有夹带开发文件**。
- 每次交付都要：升版本号（`server.py` 的 `APP_VERSION` + `electron/package.json`）、
  在 `项目历程.md` 顶部**加一节新版本**（顺手更新那张版本索引表）、
  重新生成三份 `.docx`、跑全量测试、打包、验包。
  ⚠ 2.4.5 起版本流水**只在 项目历程.md 里写一份** —— 说明书里不再重复。
     写版本小节时顺手把「这个坑是什么、为什么这么修」写清楚，
     那是这份记录唯一的价值（只写"修了 X"等于没写）。
